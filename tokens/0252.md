# BRC-252: Compact Lineage Evidence for P2P-FT

Brandon Cryderman / HandCash (brandongcryderman@gmail.com)

**Status:** Draft (proposed number, not a BSVA assignment)

## Abstract

This document specifies how a [BRC-251](./0251.md) lineage stays short as a token trades. The validity rules do not change. A wallet still accepts an output only when a walk to the deploy succeeds, or when it stops at a verdict it recorded itself.

Three mechanisms keep later packages small. Transaction bodies are identified by txid, so any host can serve them and the receiver checks the hash. A sender omits ancestors behind outputs the recipient has already verified. When several inputs cover an amount, the sender prefers the inputs that leave the shortest remainder for that recipient. A compressed proof of an older walk may replace those bodies only when the recipient can verify the proof. This document registers no proof system.

## Motivation

[BRC-251](./0251.md) already lets a wallet stop a walk at an output it has verified before. That verdict is local. The next payment to someone else still carries every ancestor that recipient has not checked, and a first payment of a long-lived token carries the whole walk.

The bodies are ordinary transactions. Their txids are the names. Repeating a script check the recipient has already done, or shipping a body the recipient already holds, is the cost that grows with trading. Both shrink without a trusted party: send the suffix the recipient lacks, fetch any gap by txid, and spend the branch that makes the suffix short. A proof that compresses a finished walk is the same rule, applied to the script checks themselves. It is accepted only when verification of the proof replaces the walk.

A host that stores or forwards bodies is a cache. Its signature over an output is not a verdict.

## Specification

### Bodies

A same-token transaction is named by its txid. Any party MAY store or serve the body: the wallet itself, another device of the same vault, a counterparty, or a public host.

A receiver MUST accept a served body only when the body hashes to the requested txid. A body that does not hash to the txid is not that transaction. A host that withholds a body delays the walk. It cannot make a different body pass.

A wallet MAY keep one cache of bodies, shared across tokens, transfers and its own devices. Copying a body to another device copies the bytes. The receiving device still hashes them, and it still runs or resumes the walk under BRC-251.

### Recorded frontier

A wallet's **frontier** for a token is the set of outpoints of that token for which it holds a recorded BRC-251 verdict.

When a recipient acknowledges a BRC-251 transfer, the sender MAY record that recipient as holding a verdict for each value output of that transfer which the sender itself verified. That record is a hint about what a later package may omit. It is not a verdict for the sender, and it is not a verdict the recipient can borrow from the sender.

### Packages

To cover a spent outpoint for a recipient, the sender walks same-token inputs toward the deploy and includes each body until every branch meets one of:

- the deploy;
- an outpoint in the recipient's frontier, as the sender recorded it.

Bodies behind that frontier MAY be omitted. If the sender has no frontier for the recipient, the package carries the walk BRC-251 already requires.

The recipient resumes its own walk at the new outputs:

1. If it holds a recorded verdict for the outpoint, it stops.
2. Otherwise it takes the body from its cache or fetches it by txid, checks the hash, and checks that transaction under BRC-251.
3. It continues into each same-token input.

A branch that arrives already cut off is finished only when step 1 applies to the missing parent. If the recipient has no verdict there, it fetches that parent and continues. A fetch that fails leaves the output unverified. The sender's decision to omit a body never makes the output verified.

### Which inputs to spend

When more than one set of verified inputs covers the amount, the sender SHOULD choose a set that minimizes the number of bodies the package above includes for that recipient. Ties SHOULD be broken in favor of inputs this wallet verified most recently.

The choice does not affect validity. A package that takes an older branch is still a valid transfer. The recipient walks the suffix it receives.

### Compressed proof

A compressed proof claims that a BRC-251 walk succeeds for one outpoint, so a later wallet can skip the bodies behind it.

The proof is bound to an **evidence root**. The root is `SHA-256` over the txids of every same-token transaction in that walk, including the deploy and the transaction that created the outpoint. Each txid is its 32 display-order bytes. The txids are sorted as raw bytes, then concatenated.

A proof type is a name registered by a revision of this document or by a companion document. The registration states the bytes of the proof and a verification procedure. The procedure MUST accept or reject without a trusted signer, and MUST reject a proof whose evidence root, token id, outpoint or amount is not the one presented.

This document registers no proof type.

A wallet that receives a proof of an unregistered type, or a proof its verifier rejects, MUST ignore the proof and walk the bodies. A wallet that receives a proof its verifier accepts MAY stop the walk at that outpoint. The transfer's own suffix, from the spent inputs forward, is still walked in bodies. Accepting the proof verifies the token rules for the skipped prefix. It does not decide whether the new transaction is mined.

## Security considerations

- **Hints omit bytes.** A sender can omit a body the recipient still needs. The recipient fetches it or leaves the output unverified.
- **Caches serve bytes.** A host can refuse a txid. It cannot substitute a body, because the hash would fail.
- **Frontiers are per wallet.** One recipient's acknowledgement says nothing about another recipient, and nothing about a reinstalled wallet that lost its verdicts. That wallet fetches what it no longer holds.
- **Proofs bind a root.** A proof that checks for one evidence root fails for another. Until a type is registered, no proof skips a walk.
- **Spending an old branch is valid.** The input rule changes the size of the package, not the result of the walk.
- **Finality is unchanged.** A verified unmined output is still unconfirmed under BRC-251.

## Implementations

- **HandCash** implements BRC-251 recorded verdicts and fetches a missing ancestor by txid. It does not yet trim packages to a recipient's frontier, choose inputs for that suffix, or accept a compressed proof. Those are specified here.
